# claude-remote

Run `${CLAUDE_SKILL_DIR}/scripts/claude-remote [--root DIR] [--name NAME] [--config-dir DIR] [--server [--spawn MODE]] [--trust] [--install-boot | --uninstall-boot] <repo-name | /full/path>`.

- A bare name (or fragment) is matched against git repos within 3 levels of the root. Root defaults to `~/Workspace`; override with `--root DIR` or `CLAUDE_REMOTE_ROOT`.
- An argument containing `/` (or `.`, `..`, `~/...`) is used directly as the working directory; no `.git` required.
- `--name NAME` sets the Remote Control name shown on claude.ai (default: the directory name). It may contain only letters, digits, `_` and `-`; other names exit 64. The tmux session becomes `claude-<name>-<path-hash>`.
- `--config-dir DIR` sets the Claude account (`CLAUDE_CONFIG_DIR`) the session runs in. Default: the invoking shell's `CLAUDE_CONFIG_DIR`, so the session uses the account you ran the skill from; unset means Claude's default account. The tmux server does not inherit the caller's environment, so the script launches `claude` through `env`, which sets (or unsets) `CLAUDE_CONFIG_DIR` explicitly. A relative DIR is made absolute without resolving symlinks, so the session and unit names stay stable if a symlink is retargeted. Sessions started before this flag existed keep the account of the tmux server that created them and are reused under the same name: `tmux kill-session` them and rerun. A nonexistent DIR exits 66, except with `--uninstall-boot`. The boot unit name includes the account, so run `--uninstall-boot` from the same account as `--install-boot`; units installed before this flag existed need `env -u CLAUDE_CONFIG_DIR` in front of the command.
- `--server` runs `claude remote-control --name <name>` instead of an interactive session. The server accepts several sessions started from claude.ai projects or the phone app, each in the target directory; it has no conversation of its own to resume, so it runs without `claude-pane-loop`. The tmux session and boot unit get a `-server` suffix (`claude-<name>-server-<path-hash>`), so one repo can host both kinds. Use `--server` with `--uninstall-boot` to remove the server's unit. `--spawn same-dir|worktree|session` (only with `--server`; other values and use without `--server` exit 64) is passed to `claude remote-control --spawn`. Omitting the flag uses the mode saved for the folder (chosen at Claude's own prompt or toggled with `w` in the pane), or `same-dir` when none is saved; the flag overrides it for that run only and saves nothing. `session` exits when its session ends; nothing restarts the tmux session, and a boot unit only starts it again at the next boot. `--settings` applies as below, and `claude remote-control --settings` needs Claude Code v2.1.321 or later; an older CLI rejects it and the server does not start.
- `--trust` answers the "trust this folder" dialog on a new session by sending Down+Enter to the pane. With `--server` it answers the server's `Trust <directory>? [y/N]` question with `y` + Enter instead, and stops waiting once the pane shows `Connected`. Claude Code persists the answer per directory, so it only matters on first run. Pass it only when the user asked to trust that directory.
- `--install-boot` writes `~/.config/systemd/user/claude-remote-<name>-<path-hash>.service`, runs `loginctl enable-linger $USER` so the user manager starts at boot without a login, and enables the unit now. The unit waits for `network-online.target` and a successful probe of `api.anthropic.com` before starting, and retries after a failure (`Restart=on-failure`). It captures the current `PATH` and `CLAUDE_REMOTE_SETTINGS` (when set) and bakes the resolved config dir into `ExecStart`, so run it from a shell where `claude` and `node` resolve. Combine with `--name` and `--trust` to bake them into the unit.
- `--uninstall-boot` disables and removes that unit; the tmux session keeps running.
- When `claude-pane-loop` is on `PATH` or at `~/.dotfiles/bin/claude-pane-loop`, claude runs under it, so Cozempic's typed `cd '<dir>' && claude … --resume <id>` line can restart claude in the same pane. Without the loop the pane and its tmux session end when claude exits, and a Cozempic reload cannot resume it. A session started before the loop was installed has no loop until it is recreated; ending it with `tmux kill-session` interrupts any work in progress, so ask the user before doing that, then rerun the skill.
- The session runs `claude --remote-control <name> --settings $CLAUDE_REMOTE_SETTINGS` (`claude remote-control --name <name> --settings …` with `--server`). The variable has no default; unset, empty or a nonexistent path omits `--settings`.
- When `claude-env-load` is on `PATH` or at `~/.dotfiles/bin/claude-env-load`, claude (plain and `--server`) runs under it, so `~/.config/dotfiles/secrets.env` and the newest nvm node directory reach the session; a tmux pane reads no shell profile. The loader skips a secrets file that is not owner-only and warns. Without it the session gets only the environment the tmux server has. Restart a session started before the loader existed to pick it up.
- Under the loader the session also gets the dotfiles OTel env: the command carries `CLAUDE_OTEL_ACCOUNT=main`, or `<name>` for `--config-dir ~/.claude-<name>`, which `claude-env-load` turns into the account's labels. Any other `--config-dir` name sends none. Needs a `claude-env-load` that knows `CLAUDE_OTEL_ACCOUNT` (dotfiles PR #158); older ones ignore the variable.

Outcomes:

- Exit 0: report the session name, repo path, and the `tmux attach -t <session>` line from the output.
- Exit 2 (ambiguous): show the candidate paths and ask which one, then rerun with the full path.
- Exit 66 (config dir missing): tell the user the `--config-dir` path does not exist; do not ask about repos.
- Exit 1 (no match): list repos with `find <root> -maxdepth 3 -name .git -prune -printf '%h\n'` and ask which was meant.

The command is idempotent: an existing `claude-<name>-<path-hash>` tmux session (the hash is the first 6 hex of the SHA-1 of the resolved path plus the config dir when set, so same-named repos and different accounts get separate sessions) is reused, not duplicated.
Boot failures: `journalctl --user -u claude-remote-<name>-<path-hash>`.
Stop a session with `tmux kill-session -t <session>` (name printed by the script; `tmux ls` lists them).
Never start the session inside the current terminal; the tmux session must stay detached.
Requires `tmux`; `--install-boot` also requires systemd.
